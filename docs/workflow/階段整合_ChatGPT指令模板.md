# ExhibitIQ — 階段整合指令模板 V2.0（僅專案負責人使用）

> 這份模板**不是**每個工作項目使用。只有當一個階段的兩人所有工作都已完成、各自 PR 已合併到各自 dev 主線後才使用。

```text
你是 ExhibitIQ 的階段整合規劃助手。請先閱讀《ExhibitIQ 專案總規範 V2.0》、CLAUDE.md，以及本階段驗收規格。

本次整合：Phase [1/2/3/4]
GitHub Repository：[URL]
AI 開發主線：dev/ai-intelligence
資料工程開發主線：dev/data-platform
AI 工作項目與 PR 清單：[貼入]
資料工程工作項目與 PR 清單：[貼入]
階段驗收標準：[貼入]

請產生一份可以直接交給 Claude Code 執行的「階段整合指令」，要求：
1. 先讀取 GitHub 最新 main、兩條 dev 分支、已合併 PR、檔案結構、Schemas、測試與資料版本。
2. 先輸出整合前檢查：開發計畫中未完成的工作項目、未合併 PR、共用 Schema 差異、重複模組、路徑衝突、資料格式衝突；有阻礙先報告，不要硬合併。
3. 由 main 建立 integration/phase-N，整合兩條 dev 分支；保留兩人已完成成果，不可直接覆寫或丟棄任一方程式碼。
4. 對衝突逐項判斷，優先遵守總規範與 schemas/；若涉及產品需求或架構選擇，停止並向我確認。
5. 在雲端執行單元、契約、整合及端到端測試；檢查 GitHub Actions、資料包、Skill、報告與來源追蹤。
6. 提供實際執行紀錄、失敗清單、修正內容、未解風險與可重現驗收步驟。
7. 整合完成後建立 PR，base=main，附完整測試證據；**不要自行合併 main**。
8. 我確認驗收通過後，才合併整合 PR；接著提出兩條 dev 分支安全同步 main 的操作建議，避免覆寫未合併工作。
9. 不得因競賽展示而把私有資料、金鑰或公司敏感資訊公開到 GitHub Pages。

請輸出完整、可複製、可執行的 Claude Code 指令。不要自行假設任何 PR 已合併或階段已通過。
```

## 階段驗收報告應列出

- 已完成的工作項目與 PR 連結（AI／Web Dashboard／資料工程分開）。
- 可在瀏覽器操作的 Dashboard 版本、桌機與手機截圖，以及真實資料與合成資料的標示。
- 整合後的模組清單、資料流及實際產出。
- 測試成功／失敗與證據。
- 資料完整度、引用來源、AI 分析品質與已知限制。
- 是否符合該階段 Gate，及需你決策的問題。
- `integration/phase-N` 的 PR 連結與 base=`main`。
