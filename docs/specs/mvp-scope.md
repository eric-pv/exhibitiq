# ExhibitIQ 競賽 MVP 範圍與驗收指標

> 狀態：A1-01 草稿，**Eric 合併本文件的 PR 即代表核定**。之後的修改依開發計畫流程進行。
> 依據：[`ExhibitIQ_專案總規範.md`](../ExhibitIQ_專案總規範.md) §1、§1.1、§7、§8.1；[`DEVELOPMENT_PLAN.md`](../DEVELOPMENT_PLAN.md) §3、§5、§6。
> **本文件不指定任何展覽。** 驗收的是可重用的系統能力；任何展覽的參展商數量都不是驗收指標（總規範 §1.1 強制規則）。

## 1. 分級

| 等級 | 意義 |
|---|---|
| **M** | 競賽 MVP 必做。Phase 4 驗收時缺任何一項就不通過 |
| **A** | 進階功能。時間允許時做；不做不影響驗收 |
| **F** | 未來擴充。競賽期間不做，只保留介面或資料結構 |

## 4. MVP 驗收指標

每一項都要有**可重現的證據**：自動測試、Playwright 截圖，或可在雲端重新執行的指令。

| # | 指標 | 證據 |
|---|---|---|
| V1 | **通用性：** 至少兩組不同結構的展覽資料（其中至少一組是真實、合法取得的公開資料）完成標準化 → 資料包 → AI 分析 → Dashboard 展示，**第二組資料的 PR 不修改核心程式** | A4-10 測試；第二組資料的 PR diff |
| V2 | **新增展覽：** 在 Dashboard 新增一個先前未收錄的展覽，經通用流程取得或匯入、分析，並在 Dashboard 顯示 | 操作紀錄與截圖 |
| V3 | **取得失敗也看得到：** 至少一個取得失敗或資料不足的來源，在系統狀態頁顯示原因，而且沒有阻礙其他展覽的處理 | 資料集索引與截圖 |
| V4 | **來源追溯：** Dashboard 上任一事實欄位都能追溯到 `source_id`、取得時間與快照雜湊 | 測試 |
| V5 | **AI 推論不冒充事實：** 所有推論、分類、評分都標示為 AI 推論；推論必須有依據、信心等級與不確定性（Schema 強制） | 契約測試與截圖 |
| V6 | **評分可解釋：** 每一個商機分數都能拆解到因子、依據與來源；沒有依據的因子為 0 分 | 契約測試與截圖 |
| V7 | **不虛構產品：** 產品建議只引用已核准的 BXR 產品卡（AR10） | 契約測試 |
| V8 | **完整度誠實：** 沒有官方筆數來源時顯示「未知」；不完整時數字旁邊顯示完整度 | 測試與截圖 |
| V9 | **報告一致：** 網頁報告與 PDF 使用同一份分析結果，內容一致 | 端到端測試 |
| V10 | **完整流程：** 新增或選擇展覽 → 企業 → 商機 → 產品建議 → 報告 → 匯出 PDF | Playwright 端到端測試 |
| V11 | **版面：** 桌機、平板、手機都可以操作 | 截圖測試 |
| V12 | **安全：** 前端沒有任何 Token、API Key；公開版只包含核准的內容 | 測試（W4-05） |
| V13 | **可重現：** 資料更新後可以重新產生資料包、分析與 Dashboard；兩人可以在雲端獨立執行 Skill | A4-04、A4-05 |
| V14 | **合成資料標示：** 任何合成資料在畫面與報告上都有明確標示 | 測試與截圖 |

**不作為驗收指標：** 任何展覽的參展商數量或名單完整度、預測準確度、特定展覽的資料是否取得成功。
